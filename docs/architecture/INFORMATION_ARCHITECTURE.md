# Information Architecture

**Статус:** На ревью
**Владелец:** Product Owner
**Дата последнего изменения:** 2026-08-12
**Назначение:** определить связную информационную структуру продукта (области, их назначение, владеемая информация, связи и доступность) — без визуального дизайна и без привязки к конкретной технологии рендеринга.

Настоящий документ детализирует `FR-003`/`FR-004` (`FUNCTIONAL_REQUIREMENTS.md`, область 2) и `PRODUCT_SCOPE.md`, раздел 10, отвечая на вопрос «как связно организованы уже утверждённые разделы продукта», — он не добавляет и не убирает ни одного раздела из `PRODUCT_SCOPE.md`, раздел 10, и не заменяет его как источник истины о том, какие разделы обязательны. Он не описывает визуальный дизайн, конкретные компоненты UI-библиотеки или маршрутизацию конкретного фреймворка — это предмет реализации в рамках уже утверждённого `ADR-0003`. При расхождении приоритет имеет `PROJECT_CHARTER.md`; иерархия источников истины — `DOCUMENTATION_STANDARD.md`, раздел 3.

Причина создания отдельного документа, а не расширения `LOGICAL_ARCHITECTURE.md`: `LOGICAL_ARCHITECTURE.md`, раздел 2, явно ограничивает себя логическим (не конкретным) уровнем и намеренно описывает область «Web UI» абстрактно, без перечисления конкретных разделов интерфейса. Настоящий документ фиксирует именно конкретную, но всё ещё дотехнологическую структуру разделов — отдельная зона ответственности по `PROJECT_CHARTER.md`, раздел 7.1 («каждый документ имеет одну зону ответственности»).

## 1. Принципы информационной архитектуры продукта

1. **Ничего не имитируется.** Раздел, для которого нет данных или подключённого источника, показывает явное, честное состояние недоступности (`ENGINEERING_PRINCIPLES.md`, пункт 35) — никогда пустую функциональную оболочку и никогда вымышленные данные.
2. **Существующее не переписывается, а становится доступным.** Каждый уже работающий компонент (`AiAnalysisSection`, `InsightHistorySection`, `TradeJournalView` и т.д.) переиспользуется как есть — настоящий документ описывает связность между ними, а не замену.
3. **Сущностно-ориентированная навигация.** Основные сущности продукта — Инструмент, Инсайт, Запись дневника, Заметка — уже существуют как связанные (через `insight_id`) сущности на backend; информационная архитектура делает эти связи видимыми и двунаправленными там, где это разумно, вместо изолированных страниц.
4. **Прогрессивное раскрытие.** Уже подтверждённый в коде паттерн (`InsightHistorySection`: компактный список → детали по запросу; краткий/полный режим инсайта) — общий принцип для всех областей, а не частный случай одного компонента.
5. **Плотность важнее украшательства.** Соответствует `PRODUCT_SCOPE.md`, раздел 2 («прозрачные... инсайты»,) и `ENGINEERING_PRINCIPLES.md`, пункт 66 («простота важнее модности»).

## 2. Области продукта

### 2.1 Market / Overview

- **Назначение:** точка входа; ориентация пользователя; сводка происходящего без необходимости заходить в каждый раздел по отдельности.
- **Владеемая информация:** не владеет данными — только агрегирует read-only сводки из Watchlist, недавних инсайтов, недавних записей дневника.
- **Переиспользуемые компоненты:** нет прямых — новая, тонкая страница.
- **Данные:** количество инструментов в watchlist, N последних сохранённых инсайтов, N последних записей дневника (все — уже существующие read endpoints, без новых источников).
- **Связи:** ссылается на Markets, Instrument Workspace, Insights/History, Journal.
- **Доступность:** **MVP, новое.**
- **Поведение при недоступности:** не применимо — данные всегда доступны в объёме того, что реально сохранено (в т.ч. пустое состояние — «пока нет сохранённых инсайтов», не ошибка).

### 2.2 Markets

- **Назначение:** контейнер рыночных направлений (`PRODUCT_SCOPE.md`, раздел 9): Акции, Forex, Криптовалюта, Сырьё.
- **Владеемая информация:** не владеет данными инструментов — маршрутизирует к Instrument Workspace через существующий каталог/поиск.
- **Переиспользуемые компоненты:** `WatchlistPanel.tsx` и backend `instruments/search` — **для раздела «Акции» полностью, без изменений.**
- **Данные:** список инструментов на рыночное направление.
- **Связи:** ведёт в Instrument Workspace.
- **Доступность:** Акции — **текущее** (уже работает, только рынок США — см. ниже); Forex/Криптовалюта/Сырьё — **заблокировано** (см. `TECHNOLOGY_EVALUATION.md`, раздел 14 «Многорыночные данные: стратегия провайдеров», и `ADR-0011` — Черновик, ожидает исследования Solution Architect).
- **Поведение при недоступности:** раздел рынка без подключённого источника отображает явное, нередактируемое сообщение о недоступности (например, «оценка провайдера в процессе») — **не кликабельная пустая страница, не имитация функциональности, не заглушка с формой поиска, которая ничего не найдёт.** Это прямо соответствует уже утверждённому `UJ-003` («недоступность данных раздела не блокирует навигацию — раздел открывается с отражением отсутствия данных») — новой User Journey для этого не требуется.
- **Глобальность раздела «Акции» (Phase 2.0, PO-2.0-1):** сегодняшняя реализация — только инструменты, торгуемые в США. Европейские/азиатские биржи — **утверждённое направление расширения**, не обязательство поддержать каждую биржу немедленно; реализация не начата, требует провайдерского исследования, идентичности инструмента при кросс-листинге, нормализации валюты и календаря сессий (см. `TARGET_INTELLIGENCE_CONTEXT.md`, §2.1–§2.2).
- **Market Context ≠ Markets (Phase 2.0, PO-2.0-2).** Индексы, ставки/доходности и макропоказатели **не являются пятым/шестым пунктом этого раздела** и не отображаются как торгуемые инструменты в Markets — это отдельная информационная область, см. §2.12 «Market Context (глобальный рыночный контекст)» ниже. Пересечение возможно в будущем только через отдельно одобренные производные (индексные фьючерсы/ETF) — вне текущего охвата.

### 2.3 Instrument Workspace

- **Назначение:** сущностно-ориентированный (по одному инструменту) вид: котировка, график, новости, AI-анализ, история инсайтов.
- **Владеемая информация:** не владеет — композиция уже существующих владельцев данных (`market_data`, `ai`/`insights`).
- **Переиспользуемые компоненты:** `InstrumentDetailsView.tsx`, `PriceChartSection.tsx`, `InstrumentNewsSection.tsx`, `AiAnalysisSection.tsx`, `InsightHistorySection.tsx` — **100% без изменений.**
- **Данные:** всё, что уже течёт через эти компоненты сегодня.
- **Связи:** доступен из Markets; содержит ссылки в Journal (уже реализовано — «Добавить в дневник») и, после утверждения Notes (`PO-4`), в Notes.
- **Доступность:** **текущее.**
- **Поведение при недоступности:** уже реализовано и не меняется этим документом (независимая деградация карточки/графика/новостей/AI-секции, см. предыдущие задачи).

### 2.4 Insights / History

- **Назначение:** сквозной, межинструментный обзор всех сохранённых инсайтов — самостоятельный раздел «История», который `PRODUCT_SCOPE.md`, раздел 10, называет как отдельный пункт (сегодня реализован только как часть Instrument Workspace).
- **Владеемая информация:** не владеет — представление уже существующих данных `insights`/`evaluations`.
- **Переиспользуемые компоненты:** паттерн `InsightHistorySection.tsx` (компактный список + детали по запросу + короткий/полный режим) переиспользуется целиком; требуется новый, аналогичный по форме backend-эндпоинт со сквозным (не по одному тикеру) списком.
- **Данные:** все сохранённые инсайты пользователя, с оценкой/результатом.
- **Связи:** элемент истории ссылается на свой инструмент (Instrument Workspace) и на связанную запись дневника, если есть.
- **Доступность:** **MVP, недостающее** (малое расширение существующего паттерна, не новый модуль).
- **Поведение при недоступности:** пустой список — «Сохранённых AI-анализов пока нет» (уже используемая формулировка), не ошибка.

### 2.5 News / Events

- **Назначение:** сквозной, межинструментный вид новостей; в перспективе — экономический календарь.
- **Владеемая информация:** не владеет — представление `market_data`/будущего календаря.
- **Переиспользуемые компоненты:** паттерн `InstrumentNewsSection.tsx` (сегодня только по инструменту).
- **Данные:** новости (с дедупликацией/переводом, см. `FUNCTIONAL_REQUIREMENTS.md`, FR-015/FR-060 — статус build-gap, не doc-gap); календарь — `FR-010`.
- **Связи:** новость ссылается на свой инструмент, если применимо.
- **Доступность:** сквозной новостной список — **MVP, недостающее**, малое расширение; Календарь — **Post-MVP**, как уже зафиксировано `FR-010`.
- **Поведение при недоступности:** раздел Календарь до реализации отображает явное «раздел запланирован на более поздний этап» — не пустая таблица событий.

### 2.6 Journal

- **Назначение:** дневник сделок пользователя.
- **Владеемая информация:** `journal_entries`, опциональная ссылка на `insight_id`.
- **Переиспользуемые компоненты:** `TradeJournalView.tsx`, `journal-api.ts` — **100% без изменений.**
- **Данные:** уже реализовано полностью.
- **Связи:** запись дневника ссылается на инсайт и (через инсайт) на инструмент — сегодня однонаправленно (инсайт → «Добавить в дневник»); настоящая карта фиксирует, что обратная ссылка (запись дневника → инструмент/инсайт, видимая из самой записи) — желаемое улучшение связности, не новая функция, реализуемая при появлении Insights/History.
- **Доступность:** **текущее.**
- **Поведение при недоступности:** не применимо — уже работает.

### 2.7 Notes

- **Назначение:** личные текстовые заметки, опционально привязанные к инструменту и/или инсайту (`PO-4`).
- **Владеемая информация:** новый `notes`-модуль (`MODULE_BOUNDARIES.md`, раздел 14, обновляется этой же задачей).
- **Переиспользуемые компоненты:** CRUD/маршрутный паттерн `journal/` переиспользуется почти буквально — на уровне архитектурного паттерна, не общего кода.
- **Данные:** текст заметки, опциональный `ticker`, опциональный `insight_id`.
- **Связи:** аналогично Journal — из Instrument Workspace и/или из Insights/History.
- **Доступность:** **MVP, недостающее** (`PO-4` одобрено, реализация не начата).
- **Поведение при недоступности:** до реализации — раздел не отображается в навигации вообще (не «заглушка», т.к. ещё не запланирован к отдельному Phase 1; появляется в навигации только вместе с реализацией).

### 2.8 Settings

- **Назначение:** отображение подключённых источников, базовая диагностика (`FR-053`/`FR-056`, SHOULD/MVP).
- **Владеемая информация:** конфигурация уже существует (`config.py`, `main.py` lifespan state) — раздел только показывает её в режиме только для чтения.
- **Переиспользуемые компоненты:** нет — новая, минимальная страница.
- **Данные:** статус подключённых источников (Twelve Data/Finnhub/xAI — сконфигурирован/не сконфигурирован), без значений секретов.
- **Связи:** нет.
- **Доступность:** **MVP, недостающее**, малый объём.
- **Поведение при недоступности:** не применимо.

### 2.9 Forecast / Thesis (Phase 2.0, концептуально, не реализовано)

- **Назначение:** отображение структурированного, объективно проверяемого прогноза/тезиса (`docs/architecture/FORECAST_CONTRACT.md`) как дополнения к текущему инсайту в Instrument Workspace — не отдельная страница верхнего уровня, а раскрытие внутри уже существующей области 2.3.
- **Владеемая информация:** не владеет — представление будущих данных `analysis`/`insights` (расширение, не новый владелец данных; см. `MODULE_BOUNDARIES.md`).
- **Переиспользуемые компоненты:** паттерн прогрессивного раскрытия `AiAnalysisSection.tsx`/`InsightHistorySection.tsx` — концептуально переиспользуется, конкретный компонент не спроектирован этим документом.
- **Данные:** направление, категориальная уверенность, доказательства, базовый/бычий/медвежий сценарии, условия инвалидации, момент повторной проверки, состояние «нет качественной возможности» (`FR-061`, `FR-062`).
- **Связи:** доступен из Instrument Workspace; связан с Monitor (§2.10), если тезис отслеживается во времени.
- **Доступность:** **Future** (направление одобрено PO-2.0-6, реализация не начата).
- **Поведение при недоступности:** до реализации — не отображается в навигации; текущий инсайт (область 2.3) продолжает работать без изменений.

### 2.10 Monitor (Phase 2.0, концептуально, не реализовано)

- **Назначение:** отображение текущего состояния ранее сформированных тезисов во времени (действителен / ослаблен / инвалидирован / истёк) без ручного повторного запроса анализа (`FR-063`, `UJ-033`).
- **Владеемая информация:** **не определена этим документом.** Является ли Monitor отдельным логическим модулем `monitoring` или расширением `jobs`/`evaluations` — открытый архитектурный вопрос, вынесенный в `docs/decisions/ADR-0012-realtime-and-background-monitoring-runtime.md` (Черновик) и `MODULE_BOUNDARIES.md`; этот документ описывает только видимую пользователю область, не владение данными.
- **Переиспользуемые компоненты:** не определены — новая область.
- **Данные:** состояние тезиса, причина перехода состояния, история проверок (расширяет уже утверждённые `FR-039`/`FR-040`).
- **Связи:** доступен из Forecast/Thesis (§2.9) и из Insights/History (§2.4, ссылка на результат автоматической проверки, уже описанной `UJ-015`/`UJ-016`).
- **Доступность:** **Future** (направление одобрено PO-2.0-10/PO-2.0-11; сама область — не автономное принятие торговых решений, только отображение состояния).
- **Поведение при недоступности:** до реализации — не отображается в навигации.

### 2.11 Learning / Accuracy (Phase 2.0, концептуально, не реализовано)

- **Назначение:** отображение агрегированной точности прошлых прогнозов по сегментам (инструмент/горизонт/рынок) — видимая часть стадийной дорожной карты обучения/калибровки (PO-2.0-12, Stage 2–3).
- **Владеемая информация:** не владеет — представление `evaluations` (владение калибровкой на уровне модуля остаётся открытым вопросом до Stage 2, см. `MODULE_BOUNDARIES.md`, раздел 12 — не переопределяется этим документом).
- **Переиспользуемые компоненты:** не определены — новая область; вероятно похожа по форме на Insights/History (агрегирующий список), не спроектирована этим документом.
- **Данные:** сегментированная статистика точности; НЕ численная калиброванная вероятность до завершения Stage 3.
- **Связи:** доступен из Overview (сводка) и из Insights/History (переход к прогнозам конкретного сегмента).
- **Доступность:** **Future**, и только после того, как Stage 0–1 (хранение обратной связи, автоматическое измерение результата) фактически накопят данные — платформа не должна заявлять «обучение» только на основании хранения обратной связи (`PRODUCT_SCOPE.md`, раздел 31).
- **Поведение при недоступности:** до накопления достаточных данных — явное состояние «недостаточно данных для статистики точности», не пустой график и не выдуманные числа.

### 2.12 Market Context (глобальный рыночный контекст, Phase 2.0, концептуально, не реализовано)

- **Назначение:** отображение индексов, ставок/доходностей и макропоказателей как **контекста для анализа**, отдельно от торгуемых инструментов Markets (§2.2) — прямое разграничение Product Owner (PO-2.0-2).
- **Владеемая информация:** не владеет — представление будущих категорий `TARGET_INTELLIGENCE_CONTEXT.md`, §2.6 (macro), §2.16 (indices), §2.17 (rates/yields).
- **Переиспользуемые компоненты:** не определены — новая область.
- **Данные:** значения индексов, ставок/доходностей, макропоказателей и их изменение; НЕ котировки, доступные для сделки в этой области.
- **Связи:** может быть referenced из Instrument Workspace/Forecast как объясняющий контекст, помеченный типом связи (`TARGET_INTELLIGENCE_CONTEXT.md`, §2.18; `FORECAST_CONTRACT.md`, раздел 6) — не отдельный переход в навигации первой необходимости.
- **Доступность:** **Future** (категории одобрены как направление PO-2.0-2; источник данных не выбран — `PRODUCT_SCOPE.md`, раздел 30).
- **Поведение при недоступности:** до реализации — не отображается в навигации; не путается с Markets (§2.2), которая остаётся исключительно торгуемыми инструментами.

## 4. Что явно не входит в этот документ

- визуальный дизайн, макеты, компонентная библиотека (`ADR-0003` уже фиксирует стек, конкретные компоненты — предмет реализации);

- итоговые пользовательские подписи разделов («Market / Overview» и другие названия в этом документе — рабочие, не финальные, по прямому указанию Product Owner);
- визуальное представление состояния «недоступно» — только факт, что оно должно быть честным, не имитирующим работу.
