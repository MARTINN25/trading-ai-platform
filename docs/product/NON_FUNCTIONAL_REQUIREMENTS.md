# Non-Functional Requirements

**Статус:** На ревью
**Владелец:** Product Owner
**Дата последнего изменения:** 2026-08-05
**Назначение:** определить измеримые нефункциональные требования платформы и открытые целевые показатели.

Настоящий документ детализирует [`PRODUCT_SCOPE.md`](./PRODUCT_SCOPE.md) в части измеримости (см. также `ENGINEERING_PRINCIPLES.md`, пункт 69). Конкретные числовые SLA этим документом не устанавливаются, если они ещё не утверждены Product Owner. При расхождении приоритет имеет `PROJECT_CHARTER.md`; иерархия источников истины — [`DOCUMENTATION_STANDARD.md`](../processes/DOCUMENTATION_STANDARD.md), раздел 3.

## Формат требования

Каждое требование имеет стабильный идентификатор `NFR-XXX`. Для каждого требования указаны: идентификатор, категория, требование, измерение или способ проверки, целевой этап, статус числового значения (`утверждено` / `предварительно` / `требуется измерение` / `требуется решение Product Owner`), примечание.

Документ отдельно различает: задержку самого приложения, задержку внешнего источника, время ответа LLM и полное время формирования инсайта — эти четыре величины не смешиваются в одном показателе. Real-time не обещается там, где источник данных не предоставляет real-time данные.
