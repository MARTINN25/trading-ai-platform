# User Journeys

**Статус:** На ревью
**Владелец:** Product Owner
**Дата последнего изменения:** 2026-08-05
**Назначение:** определить ключевые пользовательские сценарии платформы.

Настоящий документ детализирует [`PRODUCT_SCOPE.md`](./PRODUCT_SCOPE.md) и [`FUNCTIONAL_REQUIREMENTS.md`](./FUNCTIONAL_REQUIREMENTS.md) на уровне пользовательских сценариев. UI-макеты, конкретные экраны и технологии этим документом не определяются. При расхождении приоритет имеет `PROJECT_CHARTER.md`; иерархия источников истины — [`DOCUMENTATION_STANDARD.md`](../processes/DOCUMENTATION_STANDARD.md), раздел 3.

Каждый сценарий имеет стабильный идентификатор `UJ-XXX` и описывается через: название, цель пользователя, предусловия, основной поток, альтернативные потоки, ошибки и деградацию, результат, связанные FR, этап.

**Минимальный вертикальный поток MVP** (общий для сценариев, отмеченных этапом MVP, если не указано иное): выбрать рынок → выбрать инструмент → указать горизонт → получить данные → сформировать инсайт → увидеть источники → сохранить → оценить.

## UJ-001. Первый локальный запуск

- **Цель пользователя:** запустить платформу локально в первый раз.
- **Предусловия:** платформа установлена локально; конфигурация подготовлена без хардкода секретов.
- **Основной поток:** пользователь запускает локальное окружение → платформа стартует и открывает интерфейс на русском языке → отображается основная навигация.
- **Альтернативные потоки:** отсутствуют для первого запуска.
- **Ошибки и деградация:** при некорректной конфигурации платформа сообщает об ошибке на русском языке без раскрытия секретов (см. FR-057).
- **Результат:** пользователь видит рабочий интерфейс и может перейти к навигации.
- **Связанные FR:** FR-002, FR-003, FR-054, FR-057.
- **Этап:** MVP.

## UJ-002. Вход владельца

- **Цель пользователя:** получить доступ к платформе как владелец.
- **Предусловия:** платформа запущена (UJ-001).
- **Основной поток:** владелец открывает платформу → получает доступ без внешней публичной регистрации.
- **Альтернативные потоки:** серверный deployment может потребовать дополнительной проверки (Post-MVP, см. NFR-019).
- **Ошибки и деградация:** при сбое доступа отображается безопасное сообщение об ошибке.
- **Результат:** владелец имеет доступ к функциональности платформы.
- **Связанные FR:** FR-001, FR-002.
- **Этап:** MVP.

## UJ-003. Открытие раздела рынка

- **Цель пользователя:** перейти в интересующий рыночный раздел.
- **Предусловия:** пользователь вошёл в платформу (UJ-002).
- **Основной поток:** пользователь выбирает раздел (Forex, Акции, Сырьё, Криптовалюта, Скальпинг) из навигации → открывается соответствующий раздел.
- **Альтернативные потоки:** переход из истории инсайтов напрямую в раздел, связанный с инсайтом.
- **Ошибки и деградация:** недоступность данных раздела не блокирует навигацию — раздел открывается с отражением отсутствия данных.
- **Результат:** пользователь находится в выбранном рыночном разделе; данные других разделов не смешаны (FR-004).
- **Связанные FR:** FR-003, FR-004, FR-023–FR-026.
- **Этап:** MVP.

## UJ-004. Выбор инструмента

- **Цель пользователя:** выбрать конкретный торговый инструмент для анализа.
- **Предусловия:** пользователь находится в рыночном разделе (UJ-003).
- **Основной поток:** пользователь выбирает инструмент из списка, доступного в разделе → инструмент становится активным контекстом.
- **Альтернативные потоки:** повторный выбор другого инструмента в том же разделе.
- **Ошибки и деградация:** если список инструментов недоступен из-за отказа источника, отображается явное сообщение (см. UJ-010).
- **Результат:** выбранный инструмент готов для дальнейшего анализа.
- **Связанные FR:** FR-005.
- **Этап:** MVP.

## UJ-005. Запрос анализа

- **Цель пользователя:** получить аналитический инсайт по выбранному инструменту.
- **Предусловия:** инструмент выбран (UJ-004); горизонт указан (FR-006).
- **Основной поток:** пользователь запускает анализ вручную → платформа собирает данные → формирует инсайт по обязательной структуре.
- **Альтернативные потоки:** запрос краткого инсайта вместо полного (UJ-007) или наоборот (UJ-008).
- **Ошибки и деградация:** при недоступности части источников анализ продолжается с явной пометкой недостающих данных (FR-059).
- **Результат:** сформирован структурированный инсайт.
- **Связанные FR:** FR-006, FR-016, FR-017, FR-018.
- **Этап:** MVP.

## UJ-006. Уточняющие вопросы

- **Цель пользователя:** предоставить дополнительный контекст, существенно влияющий на качество анализа.
- **Предусловия:** запрошен анализ (UJ-005); ассистент определил недостаток существенной информации.
- **Основной поток:** ассистент задаёт 1–3 вопроса на русском языке → пользователь отвечает → ответы учитываются в текущем анализе.
- **Альтернативные потоки:** пользователь пропускает вопросы → ассистент продолжает с явными допущениями (FR-020).
- **Ошибки и деградация:** при противоречии ответа фактическим данным ассистент показывает противоречие, а не игнорирует его.
- **Результат:** анализ продолжается с уточнённым или явно допущенным контекстом.
- **Связанные FR:** FR-020.
- **Этап:** MVP.

## UJ-007. Получение краткого инсайта

- **Цель пользователя:** быстро увидеть сжатую версию инсайта.
- **Предусловия:** анализ запрошен (UJ-005) в кратком режиме.
- **Основной поток:** пользователь выбирает краткий режим → получает сжатую версию 10 обязательных разделов.
- **Альтернативные потоки:** переход к полному инсайту из краткого (UJ-008).
- **Ошибки и деградация:** отсутствие данных отражается даже в кратком виде, а не опускается.
- **Результат:** пользователь быстро понимает суть вывода.
- **Связанные FR:** FR-021, FR-018.
- **Этап:** MVP.

## UJ-008. Получение полного инсайта

- **Цель пользователя:** изучить инсайт со всеми деталями и основаниями.
- **Предусловия:** анализ запрошен (UJ-005) в полном режиме или пользователь раскрывает краткий инсайт.
- **Основной поток:** пользователь запрашивает полный инсайт → получает все 10 обязательных разделов подробно.
- **Альтернативные потоки:** переключение обратно на краткий вид (UJ-007).
- **Ошибки и деградация:** аналогично UJ-007 — отсутствие данных явно отражается.
- **Результат:** пользователь видит полное обоснование вывода.
- **Связанные FR:** FR-022, FR-018.
- **Этап:** MVP.

## UJ-009. Просмотр источников

- **Цель пользователя:** проверить, на основании каких источников сформирован факт.
- **Предусловия:** инсайт сформирован (UJ-005).
- **Основной поток:** пользователь открывает раздел «Ключевые факты с источниками» → видит ссылку/указание источника для каждого факта.
- **Альтернативные потоки:** переход по источнику к оригинальному материалу, если применимо.
- **Ошибки и деградация:** факт без источника считается дефектом (NFR-001) и не должен присутствовать.
- **Результат:** пользователь может проверить происхождение каждого факта.
- **Связанные FR:** FR-011.
- **Этап:** MVP.

## UJ-010. Недоступность одного источника

- **Цель пользователя:** получить полезный анализ, даже если один источник данных недоступен.
- **Предусловия:** один из подключённых источников временно недоступен.
- **Основной поток:** платформа продолжает сбор данных с оставшихся источников → инсайт формируется с явной пометкой об отсутствующем источнике.
- **Альтернативные потоки:** если недоступен единственный источник для инструмента, инсайт явно сообщает о невозможности анализа, а не выдаёт недостоверный результат.
- **Ошибки и деградация:** это и есть сценарий деградации; отказ не маскируется как достоверные данные (см. `PROJECT_SCOPE.md`, раздел 15 требования безопасности).
- **Результат:** пользователь понимает, что часть данных недоступна, и не получает ложное впечатление полноты.
- **Связанные FR:** FR-059.
- **Этап:** MVP.

## UJ-011. Устаревшие данные

- **Цель пользователя:** знать, насколько свежи данные, использованные в анализе.
- **Предусловия:** доступные данные старше ожидаемого порога свежести.
- **Основной поток:** платформа формирует инсайт и явно указывает временной срез и степень устаревания данных (раздел 9 обязательной структуры).
- **Альтернативные потоки:** пользователь может запросить повторный сбор данных.
- **Ошибки и деградация:** устаревшие данные не выдаются как актуальные.
- **Результат:** пользователь принимает решение с полным пониманием актуальности данных.
- **Связанные FR:** FR-012.
- **Этап:** MVP.

## UJ-012. Противоречивые данные

- **Цель пользователя:** понимать, когда источники или ответы пользователя противоречат друг другу.
- **Предусловия:** обнаружено противоречие между источниками данных или между ответом пользователя (UJ-006) и фактами.
- **Основной поток:** ассистент явно показывает противоречие в инсайте или в диалоге вместо того, чтобы молча выбрать один вариант.
- **Альтернативные потоки:** пользователь уточняет, какому источнику или утверждению отдать приоритет.
- **Ошибки и деградация:** противоречие не скрывается и не разрешается произвольно без объяснения.
- **Результат:** пользователь осведомлён о противоречии и может сделать осознанный выбор.
- **Связанные FR:** FR-020 (правило про противоречие ответа фактам), FR-034 (различие данных, `ENGINEERING_PRINCIPLES.md`, пункт 35).
- **Этап:** MVP.

## UJ-013. Сохранение инсайта

- **Цель пользователя:** сохранить сформированный инсайт для последующего просмотра.
- **Предусловия:** инсайт сформирован (UJ-005).
- **Основной поток:** пользователь сохраняет инсайт → запись добавляется в историю инсайтов.
- **Альтернативные потоки:** автоматическое сохранение каждого сформированного инсайта без отдельного действия (архитектурное решение вне этого документа).
- **Ошибки и деградация:** сбой сохранения отображается пользователю понятным сообщением без потери уже показанного инсайта на экране.
- **Результат:** инсайт доступен в истории (UJ-029).
- **Связанные FR:** FR-034.
- **Этап:** MVP.

## UJ-014. Оценка инсайта

- **Цель пользователя:** зафиксировать своё мнение о полезности инсайта.
- **Предусловия:** инсайт сохранён (UJ-013).
- **Основной поток:** пользователь выставляет оценку сохранённому инсайту → оценка сохраняется вместе с инсайтом.
- **Альтернативные потоки:** изменение ранее выставленной оценки.
- **Ошибки и деградация:** отсутствуют специфичные для этого сценария.
- **Результат:** оценка доступна вместе с инсайтом в истории.
- **Связанные FR:** FR-035.
- **Этап:** MVP.

## UJ-015. Проверка результата

- **Цель пользователя:** сопоставить сформированный вывод с фактическим результатом.
- **Предусловия:** инсайт сохранён (UJ-013); прошёл заданный горизонт.
- **Основной поток:** пользователь вручную фиксирует результат (MVP) или платформа выполняет автоматическую проверку (Post-MVP, FR-039) → результат сохраняется рядом с исходным выводом.
- **Альтернативные потоки:** платформа показывает базовое изменение цены за горизонт, если данные доступны (FR-037).
- **Ошибки и деградация:** при недоступности данных для проверки платформа явно сообщает о невозможности проверки, а не подставляет произвольное значение.
- **Результат:** вывод и результат связаны и сохранены неразрывно (FR-038).
- **Связанные FR:** FR-036, FR-037, FR-038, FR-039.
- **Этап:** MVP (ручная часть), Post-MVP (автоматическая часть).

## UJ-016. Просмотр ошибки и урока

- **Цель пользователя:** изучить случаи, когда вывод разошёлся с результатом, и извлечь урок.
- **Предусловия:** зафиксировано расхождение между выводом и результатом (UJ-015).
- **Основной поток:** пользователь открывает раздел «История инсайтов и ошибок» → видит классифицированное расхождение и сформированный урок (Future, FR-042–FR-044).
- **Альтернативные потоки:** в MVP пользователь видит только сырое расхождение вывод/результат без автоматической классификации.
- **Ошибки и деградация:** отсутствие урока не блокирует просмотр самого расхождения.
- **Результат:** пользователь может анализировать качество собственных прошлых выводов.
- **Связанные FR:** FR-045, FR-042–FR-044, FR-046.
- **Этап:** Post-MVP (просмотр ошибок), Future (уроки).

## UJ-017. Создание записи в дневнике

- **Цель пользователя:** зафиксировать совершённую сделку.
- **Предусловия:** пользователь совершил сделку вне или в связи с платформой.
- **Основной поток:** пользователь открывает «Дневник сделок» → вручную создаёт запись (инструмент, направление, результат) → запись сохраняется.
- **Альтернативные потоки:** создание записи со ссылкой на ранее сформированный инсайт.
- **Ошибки и деградация:** некорректный ввод отклоняется с понятным сообщением на русском языке.
- **Результат:** запись доступна в дневнике сделок.
- **Связанные FR:** FR-030.
- **Этап:** MVP.

## UJ-018. Разбор сделки

- **Цель пользователя:** получить пояснение результата сделки от ассистента.
- **Предусловия:** запись в дневнике существует (UJ-017) и связана с инсайтом.
- **Основной поток:** пользователь запрашивает разбор → ассистент формирует пояснение на основе исходного инсайта и результата.
- **Альтернативные потоки:** запись без связанного инсайта — ассистент явно сообщает об отсутствии основания для разбора.
- **Ошибки и деградация:** пояснение не должно звучать как гарантия будущего результата.
- **Результат:** пользователь получает объясняющий комментарий к сделке.
- **Связанные FR:** FR-031.
- **Этап:** Post-MVP.

## UJ-020. Сценарный анализ «Что если?»

- **Цель пользователя:** изучить гипотетический сценарий изменения условий.
- **Предусловия:** пользователь находится в контексте инструмента или инсайта.
- **Основной поток:** пользователь формулирует гипотетическое условие → ассистент формирует инсайт-гипотезу с явной пометкой, что это не факт.
- **Альтернативные потоки:** сценарий пересекает границы одного рыночного раздела — требует явного действия пользователя (`PRODUCT_SCOPE.md`, раздел 11).
- **Ошибки и деградация:** гипотеза никогда не должна отображаться как подтверждённый факт.
- **Результат:** пользователь получает явно помеченную гипотетическую оценку.
- **Связанные FR:** FR-049.
- **Этап:** Post-MVP.

## UJ-021. Настройка алерта

- **Основной поток:** пользователь задаёт условие алерта → условие сохраняется.
- **Альтернативные потоки:** редактирование или удаление ранее созданного алерта.
- **Ошибки и деградация:** некорректное условие отклоняется с понятным сообщением.
- **Результат:** алерт активен и готов к срабатыванию.
- **Связанные FR:** FR-047.
- **Этап:** Post-MVP.

- **Результат:** пользователь своевременно осведомлён о наступлении условия.
- **Связанные FR:** FR-048.
- **Этап:** Post-MVP.

## UJ-023. Быстрый скальпинг-вердикт

- **Цель пользователя:** получить быструю оценку для краткосрочной сделки.
- **Предусловия:** пользователь находится в разделе «Скальпинг» и выбрал инструмент.
- **Основной поток:** пользователь запрашивает быстрый вердикт → платформа формирует упрощённый ответ без полного цикла уточняющих вопросов.
- **Альтернативные потоки:** переход к полному анализу, если пользователю нужно больше деталей.
- **Ошибки и деградация:** при существенном недостатке данных платформа явно сообщает об ограничении, а не выдаёт вердикт с ложной уверенностью (см. UJ-024).
- **Результат:** пользователь получает быстрый, явно ограниченный по глубине ответ.
- **Связанные FR:** FR-027.
- **Этап:** MVP.

## UJ-024. Недостаток данных для скальпинга

- **Цель пользователя:** не получить вводящий в заблуждение вердикт при нехватке данных.
- **Предусловия:** запрошен быстрый вердикт (UJ-023); данные недостаточны для уверенного ответа.
- **Основной поток:** платформа явно сообщает о недостатке данных вместо формирования вердикта с завышенной уверенностью.
- **Альтернативные потоки:** пользователь может перейти к полному анализу для получения более полного контекста.
- **Ошибки и деградация:** это сам по себе сценарий деградации — управляется явным отражением ограничения (`ENGINEERING_PRINCIPLES.md`, пункт 60).
- **Результат:** пользователь не вводится в заблуждение относительно качества быстрого вердикта.
- **Связанные FR:** FR-027, FR-019.
- **Этап:** MVP.

## UJ-025. Расчёт размера позиции

- **Цель пользователя:** рассчитать размер позиции на основе параметров риска.
- **Предусловия:** пользователь ввёл параметры риска (капитал, допустимый риск на сделку и подобное).
- **Основной поток:** пользователь вводит параметры → платформа рассчитывает размер позиции.
- **Альтернативные потоки:** пересчёт при изменении параметров.
- **Ошибки и деградация:** расчёт явно помечается как вспомогательный инструмент, не гарантирующий результат сделки.
- **Результат:** пользователь получает расчётное значение для собственного решения.
- **Связанные FR:** FR-051.
- **Этап:** Post-MVP.

## UJ-026. Экспорт пользовательских данных

- **Цель пользователя:** получить копию своих данных вне платформы.
- **Предусловия:** у пользователя есть сохранённые данные (дневник, заметки, история).
- **Основной поток:** пользователь запрашивает экспорт → платформа формирует файл с данными пользователя.
- **Альтернативные потоки:** экспорт только части данных (например, только дневник).
- **Ошибки и деградация:** экспорт не должен включать секреты платформы или чужие данные.
- **Результат:** у пользователя есть читаемая копия своих данных.
- **Связанные FR:** FR-055.
- **Этап:** Post-MVP.

## UJ-027. Восстановление после ошибки интерфейса

- **Цель пользователя:** продолжить работу после сбоя интерфейса без потери данных.
- **Предусловия:** произошла ошибка интерфейса во время работы.
- **Основной поток:** платформа показывает безопасное сообщение об ошибке (FR-057) → пользователь может продолжить работу без перезапуска всего процесса, если возможно.
- **Альтернативные потоки:** если требуется перезапуск, ранее сохранённые данные (инсайты, дневник, заметки) не теряются.
- **Ошибки и деградация:** сообщение об ошибке не раскрывает внутренние детали.
- **Результат:** пользователь может восстановить рабочий процесс, сохранённые данные не утеряны.
- **Связанные FR:** FR-057.
- **Этап:** MVP.

## UJ-028. Работа в режиме частичной деградации

- **Цель пользователя:** продолжать пользоваться платформой, когда часть функциональности недоступна.
- **Предусловия:** один или несколько источников/компонентов недоступны (см. UJ-010).
- **Основной поток:** пользователь продолжает работу с доступной функциональностью (например, просмотр истории, заметки) при недоступности сбора новых данных.
- **Альтернативные потоки:** платформа явно указывает, какая функциональность временно ограничена.
- **Ошибки и деградация:** это сам сценарий graceful degradation (`ENGINEERING_PRINCIPLES.md`, пункт 21, NFR-038).
- **Результат:** платформа остаётся частично полезной вместо полного отказа.
- **Связанные FR:** FR-059.
- **Этап:** MVP.

## UJ-029. Просмотр истории инсайтов

- **Цель пользователя:** посмотреть ранее сформированные инсайты.
- **Предусловия:** есть хотя бы один сохранённый инсайт (UJ-013).
- **Основной поток:** пользователь открывает раздел истории → видит список инсайтов в хронологическом порядке → открывает конкретный инсайт.
- **Альтернативные потоки:** переход к связанному дневнику или заметке из истории.
- **Ошибки и деградация:** отсутствуют специфичные для этого сценария.
- **Результат:** пользователь может изучить прошлый инсайт в исходном виде.
- **Связанные FR:** FR-034.
- **Этап:** MVP.

## UJ-030. Фильтрация истории

- **Цель пользователя:** найти конкретные инсайты в истории по критериям.
- **Предусловия:** история содержит несколько инсайтов (UJ-029).
- **Основной поток:** пользователь задаёт фильтр (инструмент, рынок, период, оценка) → список истории сужается по критерию.
- **Альтернативные потоки:** комбинация нескольких фильтров одновременно.
- **Ошибки и деградация:** отсутствие результатов по фильтру отображается явным сообщением, а не пустым экраном без объяснения.
- **Результат:** пользователь быстро находит релевантные записи истории.
- **Связанные FR:** FR-034.
- **Этап:** Post-MVP.
